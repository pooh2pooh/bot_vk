# 🤖 VK Feed Bot

Бот для автоматической пересылки новых RSS/Atom-постов в VK. Любое число
источников, дедупликация в SQLite, шаблоны сообщений и подключаемое
AI-обогащение постов.

## Источники — это конфиг, а не код

Источник описан блоком в `config/sources.yml`. Ниже — все три реальных
источника проекта сокращённо до сути:

```yaml
sources:
  - id: lor
    name: Linux.org.ru
    type: rss
    site: lor
    url: https://www.linux.org.ru/section-rss.jsp?section=3
    requireImages: true
    enrich: openrouter
    textMode: generated
    template: templates/forum_post.yml
    promptPath: templates/ai_comment.txt

  - id: manjaro
    name: Manjaro Update
    type: rss
    site: none
    url: https://manjaro.ru/atom
    enrich: openrouter
    textMode: feed
    includeFilter: '^\[(Stable|Testing|Unstable) Update\]'
    generateWhen: '^\[(Stable|Testing|Unstable) Update\]'
```

**Добавить источник** → добавить блок. **Выключить** → `enabled: false`.
**Настроить** → поменять поля. Код при этом не трогается, нужен только
перезапуск.

### Поля источника

Все поля обязательны: лишнего или отсутствующего нет. Молчаливый дефолт
означал бы источник, который выглядит рабочим, но делает не то, что написано.

| Поле | Что значит |
| --- | --- |
| `id` | ключ в базе и в командах, строчные буквы, цифры и `-` |
| `name` | имя для логов и `/source list` |
| `type` | способ получения записей, сейчас `rss` |
| `site` | особенности сайта: `none`, `lor`, `pingvinus` |
| `enabled` | опрос источника |
| `url` | адрес фида |
| `requireImages` | выбрасывать запись без картинок |
| `enrich` | `none` или `openrouter` |
| `textMode` | `feed`, `feedFull` или `generated` |
| `textLimit` | длина текста фида в сообщении, символов |
| `template` | файл шаблона сообщения |
| `pollIntervalMs` | интервал опроса |
| `requestTimeoutMs` | таймаут запросов этого источника |

Дополнительно, в зависимости от значений:

| Поле | Когда нужен |
| --- | --- |
| `promptPath` | при `enrich: openrouter` |
| `includeFilter` | фид смешивает рубрики, в ленту нужна не вся |
| `generateWhen` | AI нужен не для всех постов источника |

Проверка строгая и собирает **все** проблемы сразу: неизвестное поле, неверный
тип, сломанный regexp, рассогласование `textMode` с `enrich`. Причина — бот
запускается под pm2 и перезапускается при ошибке, а падение на первом поле
превратилось бы в серию рестартов с одним и тем же сообщением.

> **Regexp пишите в одинарных кавычках.** В двойных YAML съедает обратный
> слэш, и `^\[Stable` превратится в битый шаблон.

## Стратегия сайта: одно поле вместо двух

Особенности сайта описываются **одним** полем `site`.

Раньше их было два — `imageExtractor` и отдельный реестр чистки описаний,
связанные по имени ключа. Такая связка требует ручной поддержки: добавить
сайт значило зарегистрировать его дважды, а забыть вторую половину молча
ломало описание поста.

Теперь контракт один. Реализуйте `SiteStrategy` — и сайт описан целиком:

| Метод | Что делает |
| --- | --- |
| `images(item)` | картинки поста; разрешено догружать со страницы |
| `description(item)` | описание поста, **разметка**; текст делает адаптер |
| `imagesFromUrl(url)` | картинки по прямой ссылке — для переотправки |
| `postText(url)` | текст поста со страницы — для fallback |

Регистрация — одна строка в `src/registries.ts`:

```ts
siteStrategies.register('my-site', ctx => new MySite(ctx));
```

Стратегия создаётся **на источник**, а не хранится готовым объектом: у
каждого источника свои таймаут и свой кеш разобранных страниц. Два источника
одного сайта не делят кеш, иначе второй увидел бы картинки первого.

### Зачем стратегии ходить на страницу поста

Метод `images()` асинхронный не для красоты. У RSS есть сайты, где в фиде
лежит меньше, чем в посте:

- **linux.org.ru** кладёт в описание **только первую** картинку галереи, а
  пост состоит из десятка скриншотов. Стратегия `lor` идёт на страницу и
  достаёт все слайды.
- **pingvinus** отдаёт в RSS **пустое** описание: и картинка, и текст живут
  только на странице. Без `postText` при отказе AI в чат ушёл бы один
  заголовок.

Два предохранителя делают это безопасным:

- **Кеш.** Посты не меняются после публикации, поэтому страница разбирается
  один раз за процесс (`PAGE_CACHE_SIZE` записей на источник).
- **Потолок параллелизма.** Без него сборка тридцати новых постов шла строго
  последовательно, и время опроса росло вместе с их количеством
  (`MAX_PARALLEL_PAGE_REQUESTS`).

Ошибка страницы не отменяет пост: если из фида хоть что-то есть, отправляется
это. Если не было ничего — ошибка идёт на backoff, иначе запись молча
исчезла бы навсегда по правилу `requireImages`.

## Что бот отправляет: `textMode`

| Режим | Что уходит в сообщение |
| --- | --- |
| `feed` | текст фида, укороченный по границе слова до `textLimit` |
| `feedFull` | текст фида целиком |
| `generated` | текст, сгенерированный по `promptPath` |

`textLimit` ограничивает **текст источника** — и в режиме `feed`, и как
fallback при отказе AI. Сгенерированный текст не режется: обрезать его
значило бы выкинуть половину смысла, за который модель заплатила.

`generateWhen` — regexp по **заголовку**: генерировать только для совпавших
постов, остальные отправлять по `textMode`. Так у Manjaro английские анонсы
обновлений переводятся, а русские новости идут как есть, и платный запрос
делается только для анонсов.

Схемы генерации ровно две, и третья — ошибка на старте:

- `textMode: generated` — генерация для всех постов источника;
- `textMode: feed|feedFull` + `generateWhen` — только для совпавших.

Обёртка запроса задачу не задаёт: она передаёт модели только заголовок,
автора и текст поста в маркерах `<<<BEGIN_POST>>>`. Поэтому один
`OpenRouterEnricher` одинаково годится и для шуточного комментария, и для
перевода анонса — меняется промпт.

Промпт у каждого источника свой. Общий экземпляр обогатителя означал бы,
что промпт последнего собранного источника победил у всех остальных, и
ошибка была бы видна только по вкусу текста в чате.

### Бесплатные модели лимитируются

Модели с суффиксом `:free` работают через общий пул OpenRouter, и `429` на
них — обычное дело, а не поломка. Запрос повторяется автоматически: `429` и
`5xx` относятся к временным сбоям, а `401`/`403`/`404` — нет, потому что
повтор отозванного ключа только съедает лимит.

Если провайдер прислал `Retry-After`, пауза берётся из него — сервер прямо
называет время ожидания. Оно ограничено 15 секундами: длинная пауза хуже
отказа, потому что цикл опроса источника стоит, а пост всё равно уйдёт с
текстом автора.

Отличить лимит от проблемы с ключом просто по логу: отсутствующий ключ даёт
`401 No auth credentials found`, а `429` с `provider_name` в ответе означает,
что запрос дошёл до провайдера модели и ключ OpenRouter применился.

## Точки расширения

| Что добавить | Интерфейс | Где |
| --- | --- | --- |
| Новый тип источника (Telegram и т.п.) | `SourceAdapter` | `src/core/source-adapter.ts` |
| Новый сайт со своей разметкой | `SiteStrategy` | `src/core/site-strategy.ts` |
| Новый способ обогащения | `Enricher` | `src/core/enricher.ts` |

Каждый случай — один класс и одна строка регистрации в `src/registries.ts`.

## Направление зависимостей

```
core/  ←  sources/  ←  pipeline/, enrich/, config/, db/, vk/, templates/
```

`core/` — контракты и общая механика, и он не импортирует ничего за свои
пределы, кроме внешних npm-пакетов. Новый тип источника не может случайно
затянуть в ядро логику конкретного сайта. `src/test/architecture.test.ts`
проверяет инвариант: нарушится направление — упадёт тест, а не ревью.

## Возможности

- Любое число источников, у каждого свой интервал, таймаут и шаблон.
- Дедупликация в SQLite; первый запуск **не пересылает старые записи**.
- Отказ одного источника не влияет на остальные: свой backoff, свой цикл.
- Ошибка AI не блокирует пост — уходит текст источника.
- Картинки скачиваются с retry и отдельным таймаутом, затем грузятся в VK.
- Больше 10 изображений разбиваются на несколько сообщений.
- Логи и команды — в админ-чат, источники включаются на лету.

## 1. Установка

Требуется **Node.js 22+** и npm.

### Arch Linux

```
sudo pacman -S --needed nodejs npm base-devel
```

`base-devel` нужен для сборки нативных зависимостей, включая `better-sqlite3`,
если для текущей версии Node нет готового бинарника.

### Клонирование

```
git clone https://github.com/pooh2pooh/bot_vk.git
cd bot_vk
npm install
```

При проблемах с `better-sqlite3`:

```
npm rebuild better-sqlite3 --build-from-source
```

## 2. Настройка

### 2.1 `.env` — секреты и глобальные настройки

```
cp .env.example .env
nano .env
```

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `VK_TOKEN` | да | токен сообщества VK с правами на сообщения |
| `TARGET_CHAT` | да | id чата для публикации |
| `ADMIN_CHAT` | да | id чата или пользователя для логов и команд |
| `OWNER_ID` | да | id пользователя с административными командами |
| `USER_AGENT` | нет (`VK-Feed-Bot/2.0`) | User-Agent для всех HTTP-запросов |
| `MAX_PARALLEL_PAGE_REQUESTS` | нет (`5`) | потолок одновременных загрузок страниц **одного** источника |
| `PAGE_CACHE_SIZE` | нет (`500`) | сколько разобранных страниц держит стратегия в памяти |
| `LOG_LEVEL` | нет (`info`) | `debug`, `info`, `warn`, `error` |
| `IMAGE_DOWNLOAD_TIMEOUT_MS` | нет (`60000`) | таймаут скачивания картинки ботом |
| `VK_UPLOAD_TIMEOUT_MS` | нет (`90000`) | таймаут загрузки картинки в VK |
| `OPENROUTER_API_KEY` | нет | нужен, если хотя бы один источник использует `enrich: openrouter` |
| `OPENROUTER_MODEL` | нет | id модели |
| `OPENROUTER_MODEL_NAME` | нет | имя модели для сообщений |
| `OPENROUTER_TIMEOUT_MS` | нет (`30000`) | таймаут запроса к OpenRouter |
| `OPENROUTER_MAX_TOKENS` | нет (`700`) | лимит токенов в ответе |
| `OPENROUTER_MAX_ATTEMPTS` | нет (`3`) | попыток на запрос при временном сбое; `1` — без повторов |
| `OPENROUTER_RETRY_DELAY_MS` | нет (`2000`) | задержка перед повтором, если нет `Retry-After` |
| `DATABASE_PATH` | нет (`data/bot.db`) | путь к SQLite |
| `SOURCES_FILE` | нет (`config/sources.yml`) | путь к списку источников |

У id чатов и владельца нет значений по умолчанию намеренно: у каждого
развёртывания свои, а молчаливый default означал бы отправку сообщений не
туда.

> **Нужно ли пересобирать проект после правки `.env`? Нет.**
> `npm run build` — это просто `tsc`. Бандлера и плагинов подстановки в
> проекте нет, поэтому значения из `.env` в `dist/` не попадают и не
> запекаются. Файл читается один раз при старте процесса — достаточно
> `pm2 restart`.
>
> То же касается `config/sources.yml`. Исключение — AI-промпт: он
> перечитывается командой `/ai reload` без рестарта.
>
> Проверить, что секрет случайно не утёк в сборку:
> `grep -r "значение_переменной" dist/` — совпадений быть не должно.

> `.env` содержит секреты и не должен попадать в Git.

### 2.2 `config/sources.yml` — источники

Несекретная конфигурация, версионируется в Git. Полный пример и комментарии
— в самом файле. Бот не стартует, если указанного `template` или `promptPath`
нет на диске или файл невалиден: сообщение называет источник и путь.

## 3. Настройка AI

Модель меняется в `.env`:

```
OPENROUTER_MODEL=новый-id-модели
OPENROUTER_MODEL_NAME=Название модели
```

Промпт — файл, путь к нему указывается у источника в `promptPath`.
`templates/ai_comment.txt` — добродушно подколоть автора (LOR, Pingvinus),
`templates/announce_translation.txt` — перевести анонс (Manjaro).

После правки промпта рестарт не нужен: `/ai reload`. Текущее состояние:
`/ai status`.

## 5. Команды в админ-чате

```
/help
/status

/source list
/source check ID
/source posts ID [N]
/source resend ID N
/source resend-last ID
/source enable ID
/source disable ID

/admin list
/admin add ID
/admin remove ID

/template reload [ID]

/ai status
/ai reload
```

`/source posts` показывает последние посты источника, а `/source resend`
пересылает выбранный:

```
/source posts lor
```

```
📰 Посты источника "Linux.org.ru"

1. ✅ 01.10 16:04 🖼2
   x220+CachyOS
2. • 30.09 09:12
   Enlightenment E27. Назад в будущее

✅ отправлен · • ещё не отправлен
Переслать: /source resend ID N, где N — номер в списке.
```

```
/source resend lor 2
```

Номер — позиция в **показанном** списке, а не в базе: между двумя командами
может прийти новый пост и сдвинуть нумерацию. Поэтому выбор идёт по снимку на
момент показа, и `/source resend` до `/source posts` отвечает отказом с
подсказкой. По умолчанию список показывает 10 записей, потолок — 20.

Команды принимаются **только в `ADMIN_CHAT`** и только от пользователей,
записанных в SQLite как администраторы. `OWNER_ID` автоматически получает роль
владельца при старте. `/source enable|disable` переживает перезапуск.

## 6. Как работает обработка

```
config/sources.yml
        │
        ▼
SourceAdapterRegistry ──► RssSourceAdapter (+ SiteStrategy сайта)
        │
        ▼
   SourcePipeline ───► SQLite — дедупликация
        │
        ├── enrich: none ─────────► TemplateManager ─► VKSender ─► VK
        │
        └── enrich: openrouter
               │
               ▼
        Enricher.enrich() — ошибка не блокирует пост
               │
               ▼
        TemplateManager ─────────► VKSender ─► VK
```

Каждый источник крутится в `Scheduler` на своём цикле с собственным
backoff. Падение одного источника не затрагивает остальные.

### Первый запуск

При старте текущие записи всех источников добавляются в SQLite и помечаются
`ignored`. Старые посты не отправляются — иначе при первом запуске в чат
вывалился бы весь архив источника.

### Дубликаты и ошибки

Ключ записи — `${sourceId}:${rawId}`. Уже обработанные повторно не
отправляются. Если отправка не удалась, запись **не помечается** отправленной
и попадёт в ленту снова на следующем опросе.

Если генерация недоступна или превысила таймаут — пост всё равно уходит с
текстом источника, ошибка отдельно попадает в лог.

### Изображения

Внешние URL скачиваются ботом с retry, затем `Buffer` грузится в VK с
отдельным таймаутом. Это защищает от ошибок вида `The operation was
aborted`.

## 8. Типовой цикл

```
Новый пост источника X
   ↓
Отсев: skipIds (уже обработанные) и includeFilter — до разбора страницы
   ↓
SiteStrategy.images() — из фида и, если нужно, со страницы поста
   ↓
requireImages? нет картинки → запись отброшена
   ↓
Генерация? enrich + textMode/generatedWhen
   ├─ нет  → текст источника
   └─ да   → Enricher.enrich(), при ошибке текст источника
   ↓
textLimit по границе слова (только для текста источника)
   ↓
TemplateManager.render → VKSender.send → VK
   ↓
Отметка в SQLite
```

Отсев до разбора — не оптимизация ради оптимизации: догрузка страниц постов
ходит в чужой сайт, и без подсказки «эти записи уже обработаны» каждый опрос
оплачивал бы десятки лишних запросов ради постов, которые всё равно были бы
отброшены.

## 9. Обновление

```
git pull
npm install
npm run build
pm2 restart vk-feed-bot
```

`data/bot.db` удалять при обновлении не нужно — там дедупликация и
администраторы.

### Переезд со старой версии

Старые переменные `.env` (`FEED_URL`, `SCREENSHOTS_FEED_URL`,
`DEFAULT_POLL_INTERVAL_MS`, `DEFAULT_REQUEST_TIMEOUT_MS`,
`OPENROUTER_PROMPT_FILE`) больше не читаются. Настройки переносятся в
`config/sources.yml` и `.env` по таблицам выше.

Промпт из `OPENROUTER_PROMPT_FILE` переносится в поле `promptPath` источника.
Значения в `.env`, которых больше нет в коде, можно удалить — они просто
игнорируются, но мешают разобраться, что на самом деле влияет на бота.

Записи в `data/bot.db` совместимы: колонка `source` как хранила строку, так и
хранит, теперь это `id` источника из `sources.yml`.
